# KAGA Absolute Final — Integration Architecture

## Ownership

- Clean production baseline: deployment, public runtime allowlist, Render, packaging.
- Event Proposal: executive names, journey semantics, stops, order, durations and optionality.
- Rhino: canonical `KAGA-SOURCE-2D-V1` coordinates and physical registration.
- Illustrator: processed visual cartography only; never names or coordinates.
- Knowledge Guide: explicit enrichment only after Event Proposal admission.
- PF-2: route/map, editorial/render, cinematic/opening and quiet-identity archetypes.
- Mythic: Guest Journey A–L rail, transport story, source segmentation and illustrated default.
- Legendary: six authored stories, four lenses, Living Four-Day Masterplan, Director and continuity.
- Executive Delight: restrained live first-90-second choreography.

## Runtime composition

The app uses one canonical journey/spatial state. Source-true, illustrated and story map readings render over the same coordinates. Mythic and Delight consume the approved Guest Journey and registered geometry without copying or modifying it. Legendary lenses and Directors reuse the same journeys, stops, experiences, knowledge and map engines.

The public runtime is built from an explicit asset allowlist. It contains optimized source visuals, processed illustrated layers, the executive masterplan, sanitized registered-garden geometry and the authoritative Event Proposal PDF. Raw source and internal provenance assets are not published.

## Source authority contract

`Event name/existence → Rhino location → Illustrator appearance → Knowledge enrichment`.

No layer is allowed to exceed that role. Unmapped entities remain semantic or knowledge-only; missing positions and source times are never fabricated.
