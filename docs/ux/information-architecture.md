# Stage UX.1: بنية المعلومات العامة

## المبدأ

واجهة مَيادين هي نظام تشغيل ذكاء فعاليات قابل لإعادة الاستخدام، لا لوحة لفعالية واحدة ولا مجموعة مختبرات. البنية التالية تنظّم طرق العمل ولا تمنح صلاحيات أو تقيّد وصولًا إنتاجيًا.

| منطقة المنتج | السؤال الأساسي | المحتوى |
| --- | --- | --- |
| القيادة | ما الذي يحتاج انتباهي الآن؟ | موجز تنفيذي، قرارات معلقة، عوائق، أثر مكاني، صحة المصدر والثقة. |
| العمليات | ما الإجراء التالي ومن يملكه؟ | قائمة تدخل، جاهزية، قرارات، أدلة، تنفيذ، تحقق. |
| المكان | أين الشرط وكيف يرتبط؟ | قائمة، `2D`، `3D`، مسارات، تفاصيل الكيان. |
| التجربة | كيف تبدو التجربة المرشحة دون ادعاء تشغيلي؟ | Experience Map وExecutive Command Map وقصة الزائر والمعاينات المرشحة. |
| الإدارة التقنية | كيف نفحص الحزم والمختبرات محليًا؟ | التهيئة، التأليف، Integration، IoT، حالة البوابة، الإسقاط والتشخيص. |

## حفظ الروابط والسياق

تبدأ المنصة من `portfolio` عندما لا يوجد مشروع صالح. تظل مساحات `executive` و`command` و`spatial` و`readiness` و`decisions` و`validation` و`integration` و`iot` و`configuration` و`authoring` و`experience` صالحة، لكنها تتطلب سياق مشروع وفعالية صريحين. الاستثناء الوحيد هو `authoring&intent=new-project` لبدء مشروع جديد من دون اختيار مشروع قائم.

- الرابط القياسي هو `?project=<projectId>&event=<eventId>&workspace=<workspace>`.
- المشروع يعلو runtime الفعالية ولا يحل محله: `Selected Project -> Selected Event -> EventRuntimeConfiguration`.
- الرابط الصريح يسبق التفضيل المحلي، ولا يوجد fallback صامت إلى مشروع ديمو أو آخر مشروع.
- أي مشروع أو فعالية غير صالحين يعيدان المستخدم إلى `محفظة المشاريع` مع تفسير عربي.
- التبديل الذري يمسح اختيار العنصر والقرار والمسار والثيم والتدفقات قبل إظهار المشروع التالي.

- يظل `selectedEntityId` هو الاختيار المشترك للقائمة و2D و3D والجاهزية والقرارات وIoT.
- يظل `selectedDecisionId` عند الانتقال من تدفق المشغّل إلى مركز القرار.
- يظل runtime المحدد ونطاق الفعالية داخل الحالة الحالية؛ البحث يرشّح نتائجه إليه ولا يكشف سجلات فعالية أخرى.
- حزمة التجربة المرشحة تفتح فقط بمعرّف تجربة صريح، وتخفي التنقل التشغيلي والتقني بدلاً من مزجهما.

## إعدادات العرض

| الإعداد | الغرض | ما لا يفعله |
| --- | --- | --- |
| عرض تنفيذي | تقليل الضوضاء وإظهار الأثر والقرار والثقة أولًا. | لا يمنح دورًا ولا يمنع drill-down. |
| عرض تشغيلي | إبراز التدخل والموقع والمالك والدليل والإجراء. | لا يغيّر الحقيقة أو الحالة الأساسية. |
| عرض تقني | فتح درج الإدارة التقنية وسياق التشخيص المحلي. | لا يمثل مصادقة أو تفويضًا أو صلاحية إنتاجية. |

## الإدارة التقنية

لا تظهر المختبرات كأفعال أولية بجوار القرار والجاهزية. تفتح من درج صريح بعنوان `الإدارة التقنية` يشرح أنها تنظيم محلي للواجهة وليست نظام صلاحيات. يظل التحميل كسولًا؛ لا يحمل Integration أو IoT أو التهيئة أو التأليف عند فتح التطبيق لأول مرة.

## رحلة الدخول

1. تبدأ الرحلة من `محفظة المشاريع` وتفصل المشروع الحقيقي المرشح عن الديمو والمرجع والمؤرشف.
2. يختار المستخدم مشروعًا، ثم تُحل الفعالية الافتراضية والثيم والحزم داخل حدوده.
3. تقود `القيادة` إلى حقيقة المشروع المحدد فقط؛ KAP يبقى مرشحًا بلا جاهزية أو بيانات حية.
4. تقود `العمليات` إلى المشهد والتدفق الموحد، ثم القرارات والجاهزية والتحقق عندما تفعلها حزمة المشروع.
5. تقود `المكان` إلى قائمة أو 2D أو 3D أو هجين، مع مسح أي اختيار عند تبديل المشروع.
6. يصل الفني إلى المختبرات من الدرج داخل المشروع، ثم يعود بلا fallback أو تبديل مصدر صامت.
