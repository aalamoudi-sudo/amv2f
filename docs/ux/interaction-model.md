# Stage UX.1: نموذج التفاعل

## التدفق التشغيلي الموحد

```text
الحالة أو الملاحظة
  -> المكان
  -> لماذا يهم
  -> الدليل والثقة
  -> المالك والجهة المسؤولة
  -> الإجراء والموعد والنتيجة
```

تظهر الخلاصة أولًا في `OperatorDecisionFlow`، ثم provenance التقني عند طلب صريح. لا يفتح التدفق قرارًا جديدًا ولا يعدّل baseline أو readiness أو verified projection؛ ينتقل فقط إلى القرار الحالي في السجل ويحفظ اختياره.

## مساحة المكان الهجينة

| الوضع | السؤال الذي يجيب عنه |
| --- | --- |
| قائمة | ما الذي يحتاج الانتباه؟ |
| 2D | أين يقع؟ |
| 3D | كيف يرتبط مكانيًا؟ |
| هجين | أين يقع وكيف يرتبط في الوقت نفسه؟ |

الاختيار متزامن عبر `selectedEntityId`. لا تخترع UX.1 إحداثيات ولا تدمج هندسة Experience Intelligence المرشحة مع الهندسة التشغيلية. يظل الربط المنطقي في IoT معلّمًا كغير متحقق.

## البحث والأوامر

`Ctrl/Cmd + K` يفتح حوارًا محليًا يبحث في بيانات وقت التشغيل المنظمة: الفعالية والموقع والعناصر والمسارات والقرارات والجاهزية وأجهزة وقنوات المحاكاة ونقاط التجربة المرشحة عند السياق الصريح فقط.

- البحث يطبع العربية ويقبل الاسم العربي أو الإنجليزي أو المعرّف الثابت.
- يحصر النتائج في event الحالي، ولا يعرض فعالية أخرى.
- الأسهم وEnter وEscape تعمل، مع حبس تركيز وإعادة التركيز لمشغّل البحث.
- اختيار النتيجة يحدث الاختيار المشترك وينتقل إلى مساحة العمل الصحيحة؛ لا ينشئ بيانات بحث ثابتة أو يغير الحقيقة.

## البوابة وIoT

اختيار `المحاكاة المحلية` و`البوابة المحلية الدائمة` صريح. كل مصدر يركب منفذ `IoTDataSource` مستقلًا، ولا يتشارك snapshot أو fallback. عند الفشل تعرض الرسالة `البوابة المحلية غير متاحة — لم يتم التحويل إلى بيانات المحاكاة`. البوابة الجاهزة تعلن `بوابة محلية دائمة — لا يوجد جهاز خارجي متصل`، وكل قراءة مقبولة تبقى `مُبلّغ` وغير متحققة.

## التاريخ والروابط

التنقل بين مناطق المنتج يستخدم `history.pushState` و`popstate`، وتبقى العودة والتقدم والروابط العميقة لمساحات العمل القديمة والجديدة قابلة للاختبار. لا يخبئ التغيير مساحة تقنية خلف رابط غير قابل للعودة.
