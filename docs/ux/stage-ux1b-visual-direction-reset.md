# Stage UX.1B: Visual Direction Reset and Founder Approval Prototype

## Review objective

Stage UX.1B provides a founder-review environment for a new visual direction without replacing production screens. The rejected global dark teal treatment is replaced inside this isolated workspace by **Hybrid Light Command**: a light Mayadeen shell, event-specific editorial identity, and a focused dark spatial canvas where useful.

The review URL is:

`/?workspace=visual-direction&concept=hybrid-light`

The route is lazy-loaded, is not present in production navigation, and is rejected when `concept=hybrid-light` is absent.

## Exactly three reference screens

| Screen | Dominant question | Visual and truth treatment |
| --- | --- | --- |
| Executive Command Overview | What event is this, what requires attention, where is the impact, and what is the next action? | Image-led KAP hero, one primary governance action, three priorities, and a compact five-stage logical journey |
| Spatial Command Workspace | What can be understood spatially without inventing geometry? | Light Mayadeen shell around a canvas occupying more than 60% of the useful workspace, 2D/3D/hybrid safe states, logical relationships, and a selected-zone inspector |
| KAP Experience and Visitor Journey | How does the candidate journey read as a narrative? | Warm ivory, KAP green and gold, botanical imagery, five-stage progression, storytelling area, playback controls, and projection-preview mode |

Dense source, provenance, token, semantic, isolation, missing-input, and technical-ID evidence is contained in a secondary drawer.

## Protected platform behavior

The sprint does not alter decision lifecycle, readiness derivation, baseline/scenario/temporary-demo isolation, evidence and provenance contracts, event packages, Stage 3D integrity, Stage 3F gateway behavior, SSE, durable storage, IoT classification, route identifiers, entity identifiers, or any existing truth statement.

The theme package is local UI configuration only. It is not connected to the backend and cannot mutate operational state.

## Accessibility and layout position

- Arabic is the primary language and the workspace root is RTL.
- Primary body text resolves to at least `14px`; the workspace base is `15px`.
- Technical IDs are `12px`, LTR, and hidden behind progressive disclosure.
- All controls are native keyboard controls with a visible `3px` focus outline.
- Review drawer and projection preview trap focus, close with `Escape`, and restore the invoking control.
- Reduced-motion preference disables entrance animation.
- The required `1366×768`, `1920×1080`, and `2560×1080` command-center viewports are covered by automated review captures.

## Approval boundary

Ahmed remains the final visual authority. This branch can be reviewed, rejected, or revised without changing `main`. No production rollout, global screen replacement, backend theme service, live integration, or Stage 4 work is authorized by this prototype.

The allowed terminal status after all evidence is generated is `READY_FOR_FOUNDER_VISUAL_REVIEW`.
