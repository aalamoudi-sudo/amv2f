# Stage UX.1C: Universal Project Portfolio and Context Switcher

## Objective

Stage UX.1C turns the founder-reviewed Hybrid Light Command prototype into a universal project entry and context layer. The neutral start screen is `محفظة المشاريع`, not an event demo. Every main workspace receives one selected project and one selected event before it resolves runtime capabilities.

## Portfolio experience

The portfolio provides:

- Stable Mayadeen corporate identity and the title `المشاريع`.
- Search plus lifecycle-status and project-type filters.
- Validated recently opened projects stored as local UI preferences only.
- Candidate, demo, reference, archived, source-state, project-type, event, venue, date, and theme cues.
- An honest empty search result and a neutral no-project state.
- An Arabic invalid-project explanation without fallback.
- A functional route into the existing project-authoring flow.

Cards omit completion percentages and keep technical IDs behind a details disclosure. KAP uses its candidate green, gold, and botanical identity inside the stable purple, white, and turquoise Mayadeen shell. Project identity colors never substitute for readiness, warning, severity, or truth semantics.

## Global switcher

The project switcher is a permanent first-class shell capability in executive, operations, spatial, experience, and technical workspaces. It shows project name, lifecycle status, and source classification; opens a searchable keyboard-operable dialog; orders validated recent projects first; and returns to the portfolio.

`ArrowUp`, `ArrowDown`, `Enter`, and `Escape` work in the search list. Focus moves to search when opened and returns to the trigger on escape. Arabic RTL is preserved at all supported command-center sizes.

All three remain candidate review surfaces. After the 2026-07-21 authority assertion, the same DWG content is `approved-working-baseline` for platform development only; geometry conversion, spatial mapping, routes, readiness, and live data remain unapproved or unavailable. The five areas are still logical only. The shell status reads `حزمة تجربة مرشحة`, `لا تفعيل لخط الأساس`, and `لا توجد بيانات تشغيلية حية`.

Reference projects continue through the existing universal event runtime. Their local fictional readiness and decisions remain explicitly `temporary-demo` and cannot appear inside KAP.

## States

| State | Visible behavior |
| --- | --- |
| Boot | Registry and requested context loading message |
| No project | Portfolio, neutral switcher, and no automatic demo |
| Invalid project/event | Portfolio plus Arabic explanation |
| Archived project | Visible archived card; activation disabled |
| Switching | Full explicit atomic transition screen; no stale project content |
| No runtime capability | Honest unavailable or empty state; no legacy fallback data |
| Unsaved authoring | Confirm or cancel before any stream or state is touched |

## Visual baseline

- Light Mayadeen corporate shell.
- Mayadeen purple, white, and restrained turquoise.
- KAP green, gold, warm ivory, and botanical event identity.
- Dark spatial canvas only where it improves spatial focus.
- Immutable labeled truth and severity colors.
- No dense developer cards, unexplained IDs, invented metrics, or decorative actions.
