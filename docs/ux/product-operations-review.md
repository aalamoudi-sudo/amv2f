# مراجعة المنتج والعمليات: Stage UX.1

## الحكم

ينتقل المشغّل من الحالة إلى المكان والأثر والدليل والمالك والإجراء والموعد داخل تدفق واحد، ثم يفتح القرار المنظم عند الحاجة. لا يظهر المختبر كبديل لقرار أو تغذية حية.

## المعايير

- القيادة تقدم سؤال `ماذا يحتاج انتباهي الآن؟` قبل البطاقة العامة، وتعرض empty state صادقة إذا لم توجد حقيقة تشغيلية.
- العمليات لا تفترض أن reported تعني verified ولا أن candidate تعني baseline.
- المكان يقدّم قائمة و2D و3D وهجين، ولا يفرض 3D لكل مهمة.
- البحث يعيد النتيجة في نطاق الفعالية الحالي، فلا يخلط فعالية أخرى أو KAP المرشح ضمن runtime تشغيلي آخر.
- IoT يحافظ على الاختيار المشترك مع فصل مصدر gateway والمحاكاة وعدم وجود fallback صامت.

## غير مثبت

لم يؤكد مشغّلون حقيقيون أن التسلسل أو المصطلحات أفضل. يجب تنفيذ بروتوكول UX.2 قبل تغيير سياسة تشغيل أو احتساب قيمة أداء بشرية.
