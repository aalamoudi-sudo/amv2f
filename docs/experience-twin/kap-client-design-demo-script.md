# KAP Client Design Demo Script

## Preflight

1. Run `pnpm verify:kap-design-assets` against the private package.
2. Run `pnpm stage:kap-design-assets` and confirm the sanitized runtime
   manifest only.
3. Open the verified production-review URL and confirm the model reaches loaded
   state within five seconds.
4. Confirm browser console/network have no blocking or external-request errors.

## Guided story

1. Open the KAP portfolio card and enter the Four-Day Experience Twin.
2. Select `استكشف التصميم ثلاثي الأبعاد`.
3. State the truth boundary: the Rhino source expresses founder-approved design
   intent; the visible GLB is a diagnostic review derivative.
4. Orbit and fit the real composition; use top and isometric viewpoints.
5. Run `جولة التصميم` and explain that its cameras are generated review views,
   not a visitor route or 360 capture.
6. Switch between 31 October, 2 November and 3 November personas to show that
   context changes while geometry remains the same.
7. Show 1 November as a ceremony/design context with no operational visitor
   journey, cross-site line, or travel-time claim.
8. Open the experience, structure, truth and command lenses.
9. Select the proposed Mamar Al-Osour relation and point out that identity still
   needs founder/studio confirmation.
10. Enter `وضع عرض العميل`; keep the design-preview and unregistered wording
    visible while technical hashes stay hidden.
11. Open the missing 360 slot and explain that a genuine 2:1 panorama upgrades
    this same scene identity later.
12. Exit client mode without losing day, persona or viewpoint, then open
    `حقيقة التصميم` for technical verification if requested.

## Required closing statement

The design improves visual understanding only. It does not establish geometry,
route, HSE, completion, operational readiness, client acceptance or opening
authority.
