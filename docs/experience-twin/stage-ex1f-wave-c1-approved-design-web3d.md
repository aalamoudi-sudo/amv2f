# Stage EX.1F Wave C.1 — Founder-Approved Design Web3D

## Status

This additive wave integrates the first verified Mahmoud design derivative into
the existing Four-Day Experience Twin. It does not create a second viewer,
truth store, route model, readiness path, or project context.

The intended closure status is
`READY_FOR_FOUNDER_STAGE_EX1F_WAVEC1_DESIGN_REVIEW`. It is not a merge,
engineering, HSE, route, as-built, operational-readiness, client-acceptance, or
production-deployment approval.

## Founder authority boundary

Ahmed approved the native Rhino source as `founder-approved-design-source` for
design-intent review. The locally staged GLB remains
`derived-diagnostic-candidate` and `review-only`.

The approval permits a verified derivative to be inspected and presented as a
design preview. It does not establish:

- engineering registration, CRS, north, control points, or surveyed position;
- as-built or construction-completion truth;
- visitor-route, capacity, movement, HSE, or operational approval;
- readiness, decision, evidence, or baseline mutation;
- production cameras, studio export, textures, or 360 panorama.

The same KAP Experience Twin now provides:

- a direct `استكشف التصميم ثلاثي الأبعاد` entry from the project, Experience
  Twin, Story Map, Spatial Command, and portfolio context;
- a large, lazy-loaded Web3D canvas containing the verified real mesh

  `مشتق تصميمي للمعاينة` and `غير مسجل هندسيًا` truth;
- a `حقيقة التصميم` drawer with hashes and metrics under explicit disclosure;
- safe missing, hash-mismatch, failed, aborted, WebGL-context and missing-360
  states without a fictional fallback.

## One legal asset path

```text
private intake package
→ complete checksum inventory verification
→ native and derivative fingerprint verification
→ GLB structural and metric validation
→ atomic local staging into an ignored runtime directory
→ Experience Scene Gateway fingerprint verification
→ lazy Web3D renderer
→ existing ExperienceSelectionContext projection
```

The browser receives only a relative runtime URI. The native `.3dm`, private
directory, embedded resources and absolute paths never enter browser fixtures,
Git, JavaScript, or the review archive.

## Four-day synchronization

One shared geometry may appear in any of the four program-day contexts only
because the project configuration explicitly lists those day IDs. Changing day
or persona changes contextual copy, moment and operational projection; it does
not clone or mutate geometry.

The 1 November corrective truth remains in force:

- the day and ceremonial contexts remain visible;
- operational and shared visitor journeys are `not-applicable`;
- no cross-site line, travel duration, receiving gate, or route blocker exists;
- future technical-production activity requires a separate approved source.

## Reviews

### CTO

- The scene gateway and `DesignExperienceConfiguration` own IDs, authority,
  relationships and selection; React Three Fiber is a replaceable renderer.
- The GLB is external to Core and is loaded through an ignored local asset
  boundary after a hash check.
- Future Cesium, OpenUSD/Omniverse or another renderer can implement the same
  scene/viewpoint contract without changing project truth.
- Missing or altered assets fail closed; another project or demo is never used.

### Product Operations

- Arabic labels separate the approved source intent from the diagnostic
  derivative and missing engineering registration.
- Design interactions cannot write readiness, decisions, evidence, routes, or
  baseline state.
- URL state is validated against the active project pack; foreign scene IDs are
  rejected rather than replaced with KAP or demo content.
- Client mode is concise but never hides that the scene is a design preview.

### Experience Strategy

- Ahmed can inspect one real design composition by day and persona and present
  a bounded camera tour instead of a static image.
- A genuine visitor walkthrough still needs studio cameras, confirmed scene
  identity, production geometry/materials, registration, and approved journey
  relationships.
- Future 2:1 panoramas and studio GLBs replace adapters in the same scene slot;
  no new product page is required.

### Security and rights

- Raw sources, private paths, embedded images and GLB bytes are excluded from
  Git and review archives.
- The runtime derivative is limited to local/client review and does not imply
  redistribution rights.
- Source and derivative hashes are checked before staging and again before the
  gateway exposes a Blob URL.
- A changed or unavailable file produces an Arabic fail-closed state.

## Deferred

Production asset hosting, identity, trusted time, rights administration,
studio export acceptance, engineering registration, 360 delivery, live
services, AI, simulation, hardware and Stage 4 remain outside this wave.
