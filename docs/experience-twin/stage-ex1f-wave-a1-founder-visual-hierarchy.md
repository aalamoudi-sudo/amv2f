# Stage EX.1F Wave A.1 — Founder Visual Hierarchy and Cinematic Spatial Correction

## Boundary

Wave A.1 is a visual hierarchy and interaction correction on the existing
EX.1F Experience Twin. It does not change the experience data model, source
authority, day/persona/journey identities, spatial anchors, readiness truth, or
delivery manifests. It does not accept Wave B operational files or Wave C
studio assets, and it does not start Stage 4.

KAP remains a candidate Experience Twin. Operational readiness remains
`cannot-determine`.

## Founder findings addressed

- The global command header and repeated Experience Twin rows were replaced by
  one compact Experience Bar for project, day, persona, mode, presentation,
  truth and exit.
- Secondary spaces, map modes, source details and authoring controls remain
  available in one contextual drawer rather than occupying the default fold.
- The KAP entry is now a source-backed spatial hero with a visible
  `مرجع 2D محسن · ليس 3D أو 360°` classification.
- The Story Map and scene surface occupy the primary viewport. The inspector is
  closed by default and opens only on request or a meaningful selection.
- The journey controller is a compact cinematic overlay. Completed, current and
  upcoming states are visually distinct without changing the authored order.
- Only the selected persona's active narrative is emphasized by default.
  Unrelated persona relationships require the explicit analysis control.
- A missing or unresolved transition is displayed as a deliberate narrative
  break. No fallback route, distance, time or approved path is created.
- Client Presentation retains the calm visual language but now uses a
  source-backed spatial anchor and visual compositions for days, journey,
  scenes, command and the A/B/C delivery roadmap.
- `عرض ما وراء التجربة` keeps the selected visitor moment fixed while revealing
  visitor view, operational preparation, ownership, evidence, decision and
  expected impact in six progressive layers.

## Spatial and scene behavior

The visual shell uses the existing scene gateway and map controller. A scene
slot is stable across delivery states:

1. Today it may show an enhanced flat source reference.
2. A future validated equirectangular panorama may open in the same slot.
3. A future validated GLB/glTF may open in the same slot.

The current flat image is never projected as a panorama or presented as 3D.
Panorama, production GLB and engineering registration remain visibly missing.

## Interaction and accessibility

- The compact menu, presentation, truth, inspector and command reveal have
  Arabic accessible names and visible focus states.
- `Escape` closes transient drawers and overlays without clearing project/day/
  persona truth.
- Reduced motion disables route, hero and command-layer transitions.
- The journey rail overlays the spatial surface instead of reserving a large
  permanent strip.
- Scene-mode controls remain pointer-accessible at 1366×768; contextual actions
  move away from the 360/3D controls in scene focus.
- URL, refresh and browser history continue to restore valid project-scoped
  selection.

## Truth preservation

Wave A.1 does not claim an approved route, calibrated geometry, operational
readiness, verified evidence, live status, true KAP panorama or production KAP
3D. Source details and technical IDs are progressively disclosed, but remain
available within one click.

## Visual verification model

The A.1 review package compares five primary compositions against the committed
Wave A screenshots at 1366×768, 1920×1080 and 2560×1080:

- Experience entry.
- Story Map.
- Persona journey.
- Client Presentation.
- Experience-to-Command transformation.

The package also captures unresolved narrative truth, the optional all-
relationships analysis layer, the missing production 3D state, truth detail and
the existing built/next delivery view. Pixel difference is evidence of material
composition change only; it is not treated as product acceptance by itself.
