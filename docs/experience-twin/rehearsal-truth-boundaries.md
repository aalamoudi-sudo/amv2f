# Rehearsal Truth Boundaries

## One-Way Consumption

The rehearsal layer consumes project, Experience Twin, Story Map, scene,
spatial, readiness, decision, and evidence projections. It never writes back to
their authoritative records.

| Rehearsal statement | What it means | What it never means |
| --- | --- | --- |
| moment completed | reviewed in a digital run | completed in the field |
| observation recorded | local rehearsal note | verified evidence |
| issue recorded | candidate concern | accepted defect or incident |
| decision linked | draft relationship exists | decision approved or closed |
| scene available | candidate visual can load | site is built or ready |
| map focus | semantic/candidate focus | approved coordinate or route |
| branch activated | hypothetical branch under review | operating procedure activated |
| plan frozen | candidate input fixed for rehearsal | baseline/client/program approval |
| learning derived | review proposal exists | next day changed |

## KAP Constants

- KAP readiness remains `cannot-determine`.
- Unknown does not become zero.
- Submitted content does not become verified evidence.
- Internal approval does not become client acceptance.
- Candidate anchors do not become engineering geometry.
- Story sequence does not become an approved route.
- `ZONE-SHOW-001` remains spatially unresolved.
- KAP flat design previews do not become 360 or calibrated 3D.
- Day 2 attendance remains unknown. Operational and visitor journeys, a shared
  transition, route, gate, and travel duration are not applicable rather than
  missing.
- Day 2 creates no operational checkpoint or contingency. Any future technical
  production activity needs a separate approved source.

## Mutation Guard

Plan and run contracts contain explicit flags denying baseline, readiness,
evidence-verification, decision-approval, and live-execution mutation. Semantic
validation rejects a rehashed object if any flag is enabled. Tests fingerprint
governed baseline, readiness, evidence, and spatial inputs before and after
rehearsal commands.

## Time and Identity

The current browser operator reference identifies a local rehearsal session,
not a production person. Browser time is untrusted. URLs contain scope and view
state only; they contain no credential or authority. Local storage is neither a
trust root nor a legal audit repository.

## Fail-Closed Behavior

Unknown or foreign scope, invalid source reference, dependency cycle, unsafe
content, fabricated precise time, forged completion, changed append-only
history, invalid import, unauthorized scene, and temporary-demo leakage are
rejected or shown as unavailable. No fallback to another project is allowed.
