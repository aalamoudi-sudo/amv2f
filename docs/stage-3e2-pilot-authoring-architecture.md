# Stage 3E.2 — بنية تأليف حزمة KAP المرشحة

## الحكم المعماري

الحزمة الخاصة بحفل افتتاح وتدشين حدائق الملك عبدالله موجودة كبيانات ومراجع
مصدرية وإعدادات فقط. لا يوجد فرع خاص داخل Core أو Zustand أو محرك السيناريو أو
التحقق أو العرض المكاني. مساحة التأليف محملة كسولياً مع مساحة Stage 3E.2 القائمة.

## الفصل بين الحالات

- دورة التأليف: `preview | candidate | validated-draft | frozen | rejected`.
- سياق التشغيل الحالي: `temporary-demo | baseline | scenario`.
- حزمة KAP الحالية: `candidate` مع `temporary-demo` فقط.
- لا تكتب الحزمة المرشحة إلى baseline ولا تنشئ قراراً أو جاهزية تشغيلية.
- `packageContentHash` يبقى `null` حتى يمكن إنتاج EventPackage قانوني.
- `sourceBundleHash` يستخدم صيغة المصدر القائمة `PILOT-SOURCE-v1-<sha256>`.

## التدفق

`مصادر خارج Git` → `سجل مصدر منقح` → `PilotEventPackageCandidate` →
`تحقق عقد التأليف` → `تقييم 12 بوابة` → `معاينة فقط`.

إنتاج EventPackage والتجميد والتفعيل محجوبة حالياً. هذا يمنع ملء حقول الهندسة
الإلزامية بإحداثيات أو مجسمات مختلقة لإرضاء عقد التشغيل.

## العقود العامة

- `GovernedPilotSourceRecord`: حالة المصدر وسلطته وبصمته وحقوقه وسلسلة أصله.
- `PilotActorCandidate`: هوية المرشح مستقلة عن اسم العرض والمسمى المؤسسي.
- `PilotRoleDefinition` و`PilotRoleAssignment`: الدور منفصل عن الشخص والتكليف.
- `PilotAuthorityBoundary`: اعتماد المنصة مستقل عن العميل وHSE والفتح والمسار.
- `PilotCadManifest`: مصدر قابل للاستبدال ومقارنة حتمية بلا SDK مورّد.
- `PilotEvidenceCandidate`: سجل ناقص يُحجر ولا يدخل قراراً متحققاً.
- `PilotFreezeGate`: بوابة تفشل مغلقاً وتحتاج دليلاً.

## قرار EventPackage

**دليل:** عقد EventPackage المجمّد يتطلب هندسة صالحة للعرض. المناطق الخمس لا تملك
إحداثيات أو مضلعات معتمدة.

**قرار:** لا يُنشأ EventPackage شكلي بقيم موضعية مزيفة. تعرض المنصة حزمة مرشحة
ذات هوية مصدر حتمية، وتبقي بصمة EventPackage غير مولدة حتى وصول الهندسة والسلطات.
