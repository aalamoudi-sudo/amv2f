# ADR-002: معيار ملاحظات إنترنت الأشياء المحايد للمورّد

**الحالة:** معتمد للتنفيذ المحلي  
**التاريخ:** 2026-07-16  
**صاحب القرار:** أحمد  
**المرحلة:** Stage 3F.0

## السياق

تحتاج المنصة إلى دمج حساسات وأجهزة من موردين وبروتوكولات مختلفة. ربط قلب
المنصة مباشرة بـBroker أو SDK أو Topic structure لمورّد واحد يجعل كل فعالية
مشروع تكامل جديدًا ويعرّض الحقيقة التشغيلية للتكرار والوقت غير الموثوق
والقراءات القديمة.

## القرار

تعتمد Mayadeen عقدًا مستقلاً للجهاز والـDatastream والـIoT Observation، ويجري
تحويله عبر Adapter إلى مسار Stage 3D القائم:

`CaptureEnvelope → Provenance → Validation → Append-only OperationalEvent`.

MQTT 5 وW3C WoT TD 1.1 وCloudEvents 1.0.2 ملفات توافق واختيارات تكامل، وليست
ملكية قلب المنصة أو مصدر الحقيقة. لا تدخل القراءة تلقائيًا إلى الحالة
المتحققة؛ تبقى `reported` حتى تمر بسلطة تحقق مستقلة.

## النتائج

- يمكن تبديل Broker والجهاز وEdge Gateway دون تغيير Event/Decision contracts.
- الجهاز، الأصل، المنطقة والـDatastream هويات منفصلة ومربوطة صراحة.
- التكرار والتعارض والقدم والعمل دون اتصال حالات قانونية واضحة.
- لا يوجد اتصال إنتاجي أو شراء أجهزة ضمن هذا القرار.
- أي Backend أو Command/Control أو هوية إنتاجية يحتاج ADR وتصريحًا لاحقًا.
