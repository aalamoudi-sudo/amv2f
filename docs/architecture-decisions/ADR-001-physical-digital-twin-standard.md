# ADR-001: اعتماد معيار التوأم الرقمي الفيزيائي

**الحالة:** معتمد

**التاريخ:** 2026-07-11

**صاحب القرار:** أحمد

**المرجع:** `MEIOS-PDT-STD-001 v1.0.0`

## السياق

Mayadeen Event Intelligence OS منصة عامة للفعاليات، وليست مشروعًا مخصصًا
لفعالية واحدة. المجسمات، والطابعات، والبروجكترات، وبرامج المابنج تتغير مع الزمن
والموقع، بينما يجب أن تبقى هوية العناصر، والعقود، والإحداثيات، والتكامل،
والاختبارات، وحزمة التسليم متسقة.

تثبيت أسماء أجهزة داخل قلب المنصة يخلق Vendor Lock-in ويجعل كل فعالية مشروعًا
جديدًا. ترك كل مورد يحدد طريقته يخلق نماذج غير قابلة للتكرار أو الصيانة.

## القرار

اعتماد `MEIOS-PDT-STD-001 v1.0.0` كأساس تصميم إلزامي لكل مشروع حالي ومستقبلي
يتضمن Digital-to-Physical أو Projection Mapping أو تصنيع مجسم.

يفصل القرار بين:

- Core Standard ثابت بإصدار.
- Implementation Profile يحدد فئة التنفيذ.
- Approved Equipment List قابلة للتحديث بعد التأهيل.
- Project Configuration خاص بكل فعالية.
- Waiver موثق لأي استثناء.

المنصة تبقى مصدر الحقيقة، وكل منتج خارجي يتصل خلف Adapter بإصدار موثق.

## النتائج

### إيجابية

- إعادة استخدام نفس المحرك عبر أنواع الفعاليات.
- استبدال الأجهزة دون كسر Domain Model.
- تطابق قابل للتحقق بين GLB وملفات الطباعة والمجسم والحالة التشغيلية.
- معايرة قابلة للتتبع والاستعادة.
- متطلبات موحدة للموردين والقبول والتسليم.

### تكاليف والتزامات

- يجب إنشاء Deployment Profile لكل فعالية.
- لا يعتمد أي جهاز دون First Article أو Projection Study واختبار قبول.
- يحتاج أي استثناء موافقة مكتوبة.
- يجب بناء Projection Gateway وVendor Adapter وفق العقد قبل Stage 6.

## الحدود

هذا القرار يعتمد معيار التصميم فقط. لا يصرح بشراء أجهزة أو بدء Stage 6 أو وصف
النظام الحالي بأنه معاير فيزيائيًا. تلك القرارات تبقى خاضعة لميثاق R&D وموافقة
أحمد الصريحة.
