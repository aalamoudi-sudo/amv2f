# مراجعة Strategy — Stage 3D

## القرار

Mayadeen يجب أن يملك canonical operational layer: IDs، event schema، provenance، trust، decision/action semantics، projection، وadapter conformance. لا ينبغي أن يملك كل sensor أو renderer أو workflow engine.

## Evidence

- core الحالي يقبل سجلات عامة من system/sensor/reality/human/workflow دون أسماء فعالية.
- output adapters لا تعيد الكتابة إلى truth.
- تبديل المصدر لا يغير Arabic workspace أو canonical projection.
- failure cases تظهر duplicate/conflict/authority/evidence بدل دفنها.

## التمييز المحتمل

**Inference:** منصات dashboard تجمع بيانات، ومورّدو twin يرسمون geometry، وأدوات PM تدير tasks. طبقة Mayadeen المقترحة تربط fact provenance/trust/action بالكيان المكاني وبمخرج متزامن. تصبح ضرورية فقط إذا أثبتت قرارًا أسرع وأدق ومسؤولية أوضح.

## Build / buy / partner / delay

- **Build:** canonical contracts، Arabic operational UX، Event Ontology mapping، trust/projection، conformance.
- **Buy:** sensor/reality/workflow/geospatial/AV capability commodity بعد gate.
- **Partner:** field integration، HSE/security authority design، spatial survey، specialist calibration لاحقًا.
- **Delay:** live feeds، AI، CV، simulation، workflow runtime، hardware until Stage/approval gates.

## أخطر افتراض

أن “zero-entry” ممكن دون جودة assignments/IDs/instructions. إذا كان prefill خاطئًا سيزيد الثقة الزائفة. trigger لإعادة النظر: أكثر من 2% target/context mis-assignment أو عبء تصحيح يتجاوز checklist.

## Recommendation

لا شراء. خطط Integration Lab لحالة واحدة؛ قارن بزمن/دقة CSV أو checklist، واختبر exit/export. نجاح reference simulators لا يثبت market value أو vendor fitness.
