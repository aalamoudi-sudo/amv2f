# Stage 3C.1 — Decision Integrity Hardening

## الحالة

واجهة عربية RTL للقرار المكاني والتمرين التشغيلي. كل البيانات الحالية محلية أو تجريبية؛ لا توجد حقيقة تشغيلية حية أو workflow durable أو اعتماد رسمي.

## ما كان خاطئاً

| الضعف | السبب الجذري | التصحيح |
| --- | --- | --- |
| تحول demo إلى baseline | اشتقاق السياق من طبقة المخزن فقط | حفظ سياق السجل مستقلاً عن `stateLayer` |
| اختفاء القرارات الجديدة | الاستعادة دارت على معرفات fallback فقط | دمج كل السجلات الصالحة حسب `decisionId` |
| قبول تاريخ يقفز مراحل | فحص متطلبات الحالة النهائية دون تاريخ كامل | مدقق تاريخ متسلسل وزمني |
| اختلاق مصدر تحقق وإغلاق | ملء حقول متخصصة من حقول عامة | هجرة بتحذيرات وقيم مفقودة صريحة |
| مرور عقود جزئية | cast بعد فحص محدود | بناء `DecisionRecord` حقلًا بحقل بعد نجاح المدقق الكامل |
| مراجع أدلة معلقة | عدم مطابقة IDs بقائمة الأدلة | تحقق عضوية وحالة `verified` |
| خلط الأثر بجودة البيانات | درجة واحدة بمعنيين | درجتا تشغيل وعناية بيانات مستقلتان |

## دلالات السياق

- `temporary-demo`: يبقى تجريبياً بعد التعديل والاستعادة.
- `baseline`: يبقى أساسياً ولا ينشأ إلا من مصدر أساسي صريح.
- `scenario`: overlay مؤقت؛ لا يكتب إلى demo أو baseline ولا يستعاد كحالة أساسية.
- `EventStateContext.stateLayer` يحدد طبقة العرض، ولا يعيد تصنيف `DecisionRecord.stateContext`.
- كل علاقة يجب أن تطابق سياق قرارها.

## دلالات الاستعادة

نسخة التخزين `8`. تجمع الاستعادة السجلات الصالحة وdefaults دون تكرار، ترتب IDs رقمياً، تحفظ الاختيار إن بقي صالحاً، وتستخدم اختياراً آمناً إذا اختفى. السجل المشوه يحجر مع code/path/رسالة عربية ولا يصل إلى الأولوية أو الواجهة كقرار موثوق.

## حدود التحقق الكامل

يفحص المدقق الهوية والسياق والمصدر والإنشاء والملكية والسلطة والأنواع والتواريخ والخيارات والأدلة والعلاقات والآثار والتاريخ. يجب أن يبدأ التاريخ بـdraft، وأن تكون المراجعات موجبة ومتسلسلة، وألا يقفز أو يرجع، وأن تطابق الحالة والمراجعة آخر entry. أدلة الإكمال والتحقق يجب أن تكون موجودة؛ دليل التحقق يجب أن يكون `verified`.

## ما يبقى محلياً وغير صالح للتشغيل الحي

الأسماء نصية، الساعة محلية، التخزين داخل المتصفح، والاعتماد والتحقق والإغلاق نماذج validation فقط. لا توجد هوية موثوقة، صلاحيات، تعارضات متعددة المستخدمين، evidence repository، أو سجل غير قابل للتغيير. لا يبدأ real-decision pilot تلقائياً؛ يحتاج حزمة مجمدة وموافقة أحمد وإجابات مرجعية وسلطات حقيقية وبروتوكول مشاركين.
